## 2. 单次执行规则

1. 每次领取一个依赖已满足的任务，开工先查看源码与Git状态。
2. 先写清输入、修改范围和验收；预计超过半天则拆成a/b子任务。
3. 完成代码与说明后保存本地，运行针对性检查，更新第7节，再汇报下一项。
4. 只有产物和验收证据齐全才能标记完成；计划、目录、页面能点都不等于工程完成。
5. 阶段结束再跑完整检查；没有新改动或失败，不反复全量构建。
6. Git提交/推送按团队已确认流程执行；未提交不能称为队友已可取得。

**下一项：按用户2026-11-14指令「按路线A运行，B/C暂不考虑，优先完善网页展示功能」，继续在纯静态L0/L1范围内完善前端展示；已完成训练场账户净值曲线、实验记录页类型/状态筛选、本机练习档案「登录」界面三个增量（第三项只是本机浏览器设备偏好，不构成身份认证；真实账号与会话隔离需L3 Function或L4 Supabase，而F1/F2尚未实测），用户已在本轮授权发布这三项，产物已按真实域名重建并就绪（12个HTML、9条sitemap URL、Pagefind 9页/2641词、114文件/3.2MiB），但`prepare_site`在`verify_target`步骤返回本月子路径配额已用尽，**发布未完成、线上仍是11-13内容**；配额解除后以同一actionId `a7f84954-fb97-44d7-a3f5-09945ff782cb`与完全相同输入重跑即可（源码未变无需重建）。下一个展示优先级（候选：实验室净值与费用读数可读性、候选研究页指标结构化、帮助文档补充新增交互说明含登录页与净值曲线）。** S04c前端侧的上传、预览与公开验收已在本账号新站点完成；独立后端路线不再默认为「Sites上跑FastAPI」——该目标与平台运行模型不兼容。F1/F2最小验证（Function可用性与本账户数据库/Storage可用性）是路线C的前置，按本轮指令暂缓，待展示功能收敛后再执行。路线B（外部HTTPS主机）在向官方确认「开发与部署均由Qoder完成」是否涵盖第三方部署前挂起，不自行推断合规。S03公开展示/再分发未确认，不能将数据发布门槛标为通过。
