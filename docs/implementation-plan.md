## 2. 单次执行规则

1. 每次领取一个依赖已满足的任务，开工先查看源码与Git状态。
2. 先写清输入、修改范围和验收；预计超过半天则拆成a/b子任务。
3. 完成代码与说明后保存本地，运行针对性检查，更新第7节，再汇报下一项。
4. 只有产物和验收证据齐全才能标记完成；计划、目录、页面能点都不等于工程完成。
5. 阶段结束再跑完整检查；没有新改动或失败，不反复全量构建。
6. Git提交/推送按团队已确认流程执行；未提交不能称为队友已可取得。

**下一项：S04c Sites实际上传、预览与公开部署验收，并明确独立后端路线、S03公开使用条件与S10正式契约。** S04a能力核验与S04b本地静态导出已完成，实际部署仍未完成；上传和发布前需明确范围、账户条件及用户授权。S03公开展示/再分发未确认，不能将数据发布门槛标为通过。

2026-11-11用户明确要求开始后端，先拆出无需真实数据和公网部署的S10a内部契约草案、S11a本地基础并验收。此拆分不绕过S10正式冻结、S11部署兼容或S12真实数据的前置条件。

## 5. 核对规则

- 文档/忽略规则只检查文本、路径与Git可见性。
- 交易用可手算样例验证日期、费用、资产守恒、T+1、期末、幂等、回滚和恢复。
- 研究验证窗口、未来信息、股票池限制、因子与分数可复算、收益与回撤能还原。
- 阶段末检查类型、只读lint、完整build/postbuild与五步体验。当前pnpm lint带--fix，审查时用不修复的等价命令。
- 本机pnpm入口曾触发安装检查；记录实际命令，不把工具入口问题当源码错误。
